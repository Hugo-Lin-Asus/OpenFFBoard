# 以 OpenFFBoard 為基礎對標 Simucube:人力評估

> 這是依原始碼現況做的量級推估,不是精確預算。
> - **未掌握 Simucube 的實際團隊規模、成本與內部技術**,對競品只用定性描述。
> - 人數與工期是假設值,請依自身目標、預算與時程調整。
> - 差距判斷來自讀程式碼與推論,尚未實機驗證。

## 1. 現況(依這個倉庫)

| 項目 | 現況 |
|---|---|
| 韌體 | 約 13 萬行(含 HAL 與 USB 堆疊等第三方碼),結構清楚,已能跑 FFB 方向盤 |
| 授權 | 韌體為 MIT,可商用;硬體與 Configurator 為其他倉庫,授權需另外確認 |
| 驅動核心 | 依賴 TMC4671 現成晶片,調教靠使用者自行操作 |
| 歷史 | 此 clone 只有 51 筆 commit(疑似淺層複製),其中 47 筆來自原作者,無法據此判斷社群貢獻規模 |
| 缺少的內容 | `Hardware/` 與 `Configurator/` 在此 clone 為空,硬體與 PC 軟體現況未讀到 |

## 2. 與產品級競品的主要差距

| 領域 | 差距 | 為什麼需要人力 |
|---|---|---|
| 馬達驅動 | 電流環靠使用者執行 `pidautotune`,測試電流約 15% 量程、轉子鎖住 | 產品級需要自動化、可重現的出廠校準與更完整的整定方法 |
| 控制頻寬 | FFB 迴圈預設 1 kHz(高速 USB 最高 8 kHz);速度與加速度為數位差分,作者標註濾波「待調」 | 需要更好的狀態估測與延遲分析,由控制工程師負責 |
| 編碼器 | 依各種外接編碼器類別,雜訊與解析度由使用者決定 | 產品需鎖定規格並做整合驗證 |
| 安全 | 有欠壓、過溫、E-stop、超出範圍保護,未見正式功能安全流程 | 直驅力道有人身風險,需要設計審查與故障注入測試 |
| 硬體 | 此倉庫沒有 | 功率級、散熱、EMC、安規認證 |
| PC 軟體 | Configurator 為獨立專案 | 需要穩定安裝程式、設定檔管理、自動更新、診斷工具 |
| 韌體更新 | 目前以 DFU 或 ST-Link 燒錄 | 產品需要安全升級流程與回復機制 |
| 品質 | CI 只驗證能否編譯 | 需要硬體在環(HIL)自動測試、遊戲相容性回歸測試 |
| 生態 | 方向盤 rim、快拆、踏板、遊戲整合 | 都是額外的產品線與合作 |

## 5. 主要不確定性與風險

- **驅動晶片天花板**:TMC4671 的性能上限沒有硬體數據可驗證。若目標是超越而非接近,可能需要換架構,人力會明顯增加。
- **認證與安規**:各市場要求未查證,預留時間依目標市場而定。
- **競品真實差距**:未實測或拆解過 Simucube,體驗差距為推論。
- **人才取得**:控制與功率電子的資深人員通常是瓶頸,比人數更影響進度。
- **授權與上游**:韌體為 MIT 可商用,但是否與上游同步、是否回饋社群會影響維護成本。

## 6. 建議作法

1. **先做 2 到 3 個月的差距驗證**(約 2 到 3 人):取得競品實機,定義量測指標(延遲、扭矩線性度、頻寬、漣波、熱),用 OpenFFBoard 實測對照。
2. 依結果決定走範圍 A 或 B。
3. 若走 B,先把硬體與認證路徑排在前面,因為前置時間最長。
